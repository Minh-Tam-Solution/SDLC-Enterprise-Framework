# Commit and PR conventions

Paths are relative to the SEF root; find it with the `sdlc-framework` skill ("Find SEF"). This skill matches SEF version 7. The repo's own `CONTRIBUTING.md`, `AGENTS.md` or hooks win where they are stricter.

## Steps

1. **Look first.** `git status` (never `-uall`) and `git diff --cached --stat`. A commit takes the whole index: if it already holds staged changes that are not part of this change, stop and ask how to handle them before staging anything. Nothing to commit ⇒ say so and stop.
2. **Stage by name.** `git add <path> …` for the files of this one change. Never `git add -A` or `git add .`. Keep one concern per commit; a file move and a content change go in separate commits (`standards/project-structure.md` "Moving and archiving").
3. **Secrets.** No secret in git, ever (`standards/security.md` "Secrets"). Refuse to stage `.env` files, keys, tokens or certificates; `.env.example` holds names only. Scan the staged content **before** committing with the repo's secret hook or scanner. If SEF's SECRET-1 (`scripts/rule-no-new-secrets.sh`, which reads lines added between a base and `HEAD`) is the only scanner, commit locally, run it before any push, and on exit `2` undo the local commit (`git reset --soft HEAD~1`) and remove the value; exit `1` means the scan could not run — not "clean". A secret found in the repository is treated as leaked: rotate it; deleting it does not un-leak it.
4. **Check the diff against the intent** that authorised it: extra work an agent added is unreviewed work — keep it, revert it or defer it, and say which (`standards/change-and-deployment.md` "Small changes, short branches"). A diff much larger than its ticket, or one adding a dependency, is flagged in the PR.
5. **Tests.** A deleted test, a new skip marker or a weakened assertion needs a written reason in the message and an independent review (`standards/testing.md` "Agents and tests"). Generated files are regenerated by their command, never hand-edited (`standards/documentation.md` "One home per fact").
6. **Message.** English, conventional commit form (SEF `CONTRIBUTING.md`; the 72-character subject limit is this skill's convention, not SEF's):

   ```text
   <type>(<scope>): <what changed, imperative, ≤72 chars>

   <why: the problem, the decision and its source (issue, ADR, PR), anything a reviewer must know>

   <trailers the repo or the user asks for, e.g. Co-Authored-By or Signed-off-by>
   ```

   Types: `feat` · `fix` · `docs` · `refactor` · `chore` (plus `test` if the repo uses it). Scope = the area changed, from the paths. A decision quoted in the message names who decided and where (`standards/collaboration.md` "Decisions"). Trailers are trace only; they are never authority (`adoption/adoption.md` "Agent identity").
7. **Commit**, then `git log -1 --stat` and show hash, subject and files.

## PR description

When asked to open a PR: what changed and why, the issue or decision it implements, how it was verified (commands and results, CI run on the head SHA), any drift from the intent, risk-floor paths touched, and how the task ended — `DONE`, `DONE_WITH_CONCERNS`, `BLOCKED` or `NEEDS_DECISION` (`standards/collaboration.md` "How a task ends").

## Rules

- Short-lived branch (hours to a day), merged to the main branch through the review path the repo's tier requires (`standards/change-and-deployment.md`, `controls/tiers.md`).
- Do not push, merge or approve unless the user asks; an approval by the author or the author's operator does not count (`controls/gates.md` "Approver independence").
- Hooks are a nudge; CI is the check. A local hook passing is not evidence that CI will (`controls/gates.md` "Hooks nudge; CI enforces").
